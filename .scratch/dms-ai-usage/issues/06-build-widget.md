## Question

Extend `ClaudeCodeUsageWidget.qml` per the prototype's design (ticket 2): wire the ChatGPT source script (ticket 5) alongside the existing Claude one via a second `Process`+`SplitParser` on the same/a second `Timer`, add the merged/switchable pill and split-pill settings toggle, wire the login action (ticket 4) into the popout's unavailable state for both Sources. Persist new settings (merge vs split, per-Account config for ChatGPT) via `pluginData`, following the existing settings patterns already in `ClaudeCodeUsageSettings.qml`.

## Resolution

Built as specified, with one narrowing from this ticket's original wording: [Merge icon UI prototype](02-merge-icon-ui-prototype.md)'s resolution (chosen after this ticket was drafted) settled on variant B — always-both-visible dual rings, no cycling — which ruled out the merge/split settings toggle this ticket's body still mentions. No toggle was built; that's ticket 02's decision, not an omission.

- **`get-chatgpt-usage` wiring**: added a second `Process` (`chatgptProcess`) + `SplitParser` running the ChatGPT script on the same `refreshInterval` `Timer` and the same wake-from-sleep force-refresh as the Claude `usageProcess`, so both Sources stay in sync. A new `parseChatgptLine` function parses its KEY=VALUE output into `chatgpt*` properties, separate from Claude's `parseLine` to keep the two Sources' parsing independent.
- **Reset countdown format handling**: per ticket 5's note that ChatGPT's `reset_at` is a unix timestamp (not Claude's ISO-8601 strings), added `parseResetMs(val)` which normalizes both formats to epoch-ms at parse time (digit-only test distinguishes them) — everything downstream (a new `formatCountdown` helper, mirroring the existing 7-day-format countdown text) works in ms only, so no format-detection logic leaks past the parse boundary.
- **Multi-account plumbing**: a "Custom ChatGPT Accounts" settings block (mirroring the existing "Custom Profiles" block exactly) persists `customChatgptAccounts` via `pluginData` and feeds `name=path` args into `chatgptProcess.command`, the same convention `get-chatgpt-usage` already parses. No per-account switching UI in the popout — ticket 2 scoped ChatGPT to window cards only — but the script's multi-account path is reachable rather than dead code.
- **Bar pill**: both `horizontalBarPill` and `verticalBarPill` now show two rings (Claude, ChatGPT) divided by a hairline `Rectangle`, per ticket 2's variant B. ChatGPT's ring uses its primary-window percentage; no pacing tick (ChatGPT has no pacing model).
- **Login action for ChatGPT**: `startChatgptLogin()` + a `chatgptLoginProcess` running `codex login` (bare, not `codex login status` — that subcommand only refreshes an existing token, per ticket 5; a missing-credentials state needs the actual OAuth flow). Verified directly (outside the widget) that `codex login` starts its local callback server and prints the browser URL without blocking on a tty when run headless — same non-blocking shape as Claude's `claude auth login --claudeai`, so the existing exit-code-driven re-fetch pattern applies unchanged. A separate `chatgptLoginInProgress` flag keeps the two Sources' login buttons independent.
- **Popout restructure**: header changed from "Claude Code Usage" to "AI Usage"; content is now two stacked sections with their own headers ("Claude", "ChatGPT"), matching ticket 2's no-tabs stacked-sections layout. Claude's existing subscription-line, profile selector, credentials card, and all Claude-only cards (pacing, cost, daily chart, model breakdown, all-time footer) moved under the Claude header unchanged. ChatGPT's section gets a plan-type line, its own credentials-unavailable/login card, and Primary/Secondary window cards (same ring+text card style as Claude's 5h/7d cards, no pacing tick, no cost figures — ticket 2 scoped ChatGPT to window cards only).
- Confirmed `PopoutComponent`/`PluginPopout` auto-size `popupHeight` to the loaded content's `implicitHeight` (`root.contentHeight = Qt.binding(() => item.implicitHeight + ...)` in `PluginPopout.qml`) — the widget's `popoutHeight: 740` is only an initial estimate, not a hard clip, so the added ChatGPT section doesn't get cut off.
- Added EN/FR/ES strings for all new UI text to `translations.js`, following the existing convention.
- **Verified**: `dms restart` + `journalctl --user` clean across three restarts — "Plugin loaded: aiUsage" with no widget QML errors (one pre-existing `qmllint` warning on line ~970's `?.` optional-chaining syntax predates this ticket, unrelated to these changes). Confirmed live: the merged pill renders both rings with real data (Claude "22% ↑", ChatGPT "0%", ticking as usage refreshed across restarts) — cross-checked ChatGPT's 0% against running `get-chatgpt-usage` directly (`CREDS_STATUS=ok`, `PRIMARY_UTIL=0`, real `plan_type=plus`), confirming it's genuine live data, not a silent-failure zero. Did not get a clean click-through screenshot of the open popout itself (two attempts at clicking the live bar pill via `ydotool` missed the target and landed on background windows instead) — the popout QML was verified by reading the resulting structure and confirming no runtime errors, balanced braces, and the auto-sizing behavior above, but not by eyeballing the rendered popout directly. Leaving full end-to-end popout verification (open it, check both Sections' cards, exercise the login buttons) to [Install and verify](07-install-and-verify.md), which already owns that matrix.
